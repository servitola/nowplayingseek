# nowplayingseek — agent rules

A command-line tool that reads and drives whatever macOS elected as Now Playing. `README.md` is
the front door, `docs/` the manual — read `docs/how-it-works.md` before touching
`src/system/mediaremote.js` or `src/player.js`, each bullet there was a bug first. README stays
under 100 lines: new material goes into `docs/`, at most a link here. Unfinished or undecided work
is `BACKLOG.md`. This file holds only what stays true: layout, gates, hard rules, and settled
decisions as one-liners — the reasoning behind each is in `docs/how-it-works.md`, not here.

## Stack and layout

JXA under `/usr/bin/osascript`: no dependencies, no `package.json`, no modules — except artwork,
one compiled helper loaded into `/usr/bin/perl`, never `osascript`. `make` concatenates the JS
sources in dependency order into one executable script: a symbol declared in one file is a plain
global in the files after it, so a file may only use symbols from the layers before it.

`src/` is the core — reading Now Playing and moving it. `src/features/{config,dialects,watch}`
are optional: everything a reader can decide not to look at. **The rule that decides core vs.
feature, always: a feature is something core never calls.** Folder or file name never decide it —
only whether core calls it; core never names a feature file, and never references a symbol
declared under `src/features/` — `scripts/globals.js --check` fails `make lint` if it does. The
`Makefile`'s `CORE`/`FEATURES` lists are the source of truth for which file is which; a new file
isn't built or tested until it's added to the right one.

File-by-file map, `native/artwork.m`'s separate build, and how the test build mirrors all of it —
consulted when you open the code, not before: `docs/development.md#layout`.

## Commands and gates

`make build`, `make test` (prints `N passed` and `N cli cases passed`), `make lint` (every hook on
every tracked file; needs `pre-commit`), `make install PREFIX=~/.local`. `build` and `test` also
compile `native/artwork.m`, so they need `clang` (Xcode Command Line Tools; every Homebrew machine
already has it). `pre-commit install` once after cloning; commits go through the hook, `--no-verify`
and `SKIP=` are not used here. A commit message carries no `Co-Authored-By` and no tool footer: GitHub counts a co-author as a contributor, and this repository has one. Run one `pre-commit` at a time: it stashes unstaged changes while it
works, and a second run in the same tree fails with "files were modified by this hook".

- Biome with every stable rule as an error, plus its formatter; actionlint; shellcheck and shfmt.
  Versions are pinned in `.pre-commit-config.yaml`.
- What is switched off, and why a cross-file symbol is not "undeclared", is in `biome.json` →
  `overrides`; both lists are regenerated by `make globals` from the `Makefile` lists, and `make
  lint` refuses when they are stale. `src/logic/` gets no `$` and no `ObjC`. Turn a rule off only
  when it cannot hold for JXA — say why in the commit.
- `make coverage`: lines of `src/logic/` the unit tests never reach — 100 %, and that says little,
  a reached line is not a protected one (evidence: `docs/development.md#testing`). `make
  typecheck`: TypeScript's checker over the built file, not strict. Both for development; CI runs
  neither.
- `make test-speed`: the tool is bound to a hotkey, so startup time is the product; fails when the
  median goes past ~3x a measured baseline (`docs/development.md#response-time`). Not part of
  `make test` — a shared CI runner is noise, signal only on a quiet machine.
- No `*.js` in `src/` or `test/` over 200 physical lines (Biome's own rule skips the lines of a
  template literal, the hook does not). Functions: 50 lines, 4 parameters, complexity 15.

## Architecture rules

- A new decision goes into `src/logic/` as a pure function with a test; `player.js` only wires
  reads, calls and polling around them.
- A new tunable is one entry in `SETTINGS` — default, parser, `about` line. The config reader,
  `config`, `config init` and the unknown-key check derive from that table.
- Argument errors are raised before the player is touched, so that they can be tested.
- Comments say why, never what.

## Testing

`make test` needs nothing playing and never touches perl or a real player — it drives
`test/fake-mediaremote.js` instead; a mutation run found 18 argument-check regressions only that
build catches. `make test-live` opens VLC on generated silence and walks the playback cases; run
it before a release. `make test-world` checks beliefs about VLC, QuickTime, macOS and Homebrew
against the real thing. Anything touching playback also gets a hand pass with a real player
running — look at `playing` first, never on something the owner is watching, put the position
back after. Full checklist and exit-code detail: `docs/development.md#testing`.

- A change to the tests is proven by breaking the code once and watching them fail.

paw on the knob, the finger on the key.

## Release

The `release` skill (`.claude/skills/release/SKILL.md`); `scripts/release.sh plan <version>` shows
what it would do. Nothing is pushed, tagged or published without the owner's word. Pushing the tag
is what publishes: `.github/workflows/release.yml` then builds `make dist` (see `make dist` in
`docs/development.md`) and attaches the tarball and its checksum to the release itself — nobody
runs `make dist` by hand for a release.

## Settled decisions

Verdict first; reasoning and evidence for each is in `docs/how-it-works.md`.

- Stay on JXA, no rewrite to a compiled binary — only an Apple-signed interpreter passes the Now
  Playing read gate (`docs/how-it-works.md#why-it-is-a-script`).
- Only the app macOS elected is driven; no per-app addressing — every route to a chosen app is
  silently redirected to the elected one (`docs/how-it-works.md#dead-ends`).
- Never call `SetOverriddenNowPlayingApplication` — it leaves `mediaremoted` electing nobody
  (`docs/how-it-works.md#dead-ends`).
- Chapters don't work — IINA registers no chapter handler (`docs/how-it-works.md#dead-ends`).
- No hotkeys of our own — a Carbon `RegisterEventHotKey` helper was built and dropped: it never
  received a press (`docs/how-it-works.md#limits`).
- No Mac App Store — ships a private, unentitled framework; App Store review is public-API only
  (`docs/how-it-works.md#limits`).
- No helper dylib inside `osascript` — arm64e refuses a plain arm64 mapped image
  (`docs/how-it-works.md#dead-ends`).
- Artwork through `/usr/bin/perl` is not a reversal of that — perl is plain arm64 and maps a plain
  arm64 bundle same as it always could (`docs/how-it-works.md#artwork`).
